Antes de começar

Imagina a sua caixa de ferramentas de casa. Enquanto são dez peças, tudo cabe numa gaveta só e você acha qualquer coisa em dois segundos. Quando viram trezentas, aquela gaveta vira um monte e você perde cinco minutos procurando uma chave allen. A saída não é comprar uma gaveta gigante — é separar em várias gavetas, cada uma com uma faixa de peças, e você saber de cabeça em qual gaveta procurar.

Em system design, isso se chama sharding de widgets.

component: phase 1 · badge-1 · phase-body (desbloqueada)
Parte 1 Uma gaveta só não dá conta — sharding de widgets

No Widget Store fictício, todos os widgets moram num nó só. Com 300 milhões de widgets, o disco enche e cada busca varre uma tabela gigante. Repartir os widgets em shards por hash da chave resolve os dois problemas de uma vez.

component: diagram-wrap · svg inline com marker/seta
component: callout (padrão / warn / danger)
Liga com o que você já viu A chave de sharding é a decisão mais cara de desfazer. Escolheu errado, a repartição não te salva — ela só espalha o problema por mais máquinas.
Cuidado Hash simples (% N) rebalanceia quase tudo quando você adiciona um nó. É por isso que existe consistent hashing.
Erro comum Sharding não substitui backup. Perder um shard é perder 1/N dos dados, não 0.

Parte 2 Uma cópia ou duas — replicação de widgets

Repartir resolve tamanho, mas não resolve morte de nó. Se o Shard B cai, 1/3 dos widgets somem. A resposta é manter réplicas de cada shard.

component: compare-grid · compare-col · compare-label
Opção A — sem réplica

Barato e simples. Um nó morre e você perde a fatia dele até restaurar backup.

Opção B — com réplica

Custa 2× de armazenamento, mas a réplica assume e a fatia continua servindo.

component: bloco de código (pre > code) 
// roteamento fictício de widget → shard
function shardFor(widgetId, replicas) {
  const h = hash(widgetId) % replicas.length;
  return replicas[h].healthy ? replicas[h] : replicas[h].fallback;
}

Parte 3 Quando a esteira entope — backpressure

Os widgets chegam para processamento numa esteira. Se os produtores empurram 50 mil widgets por segundo e os consumidores dão conta de 5 mil, a esteira cresce até estourar a memória. Backpressure é o sinal de volta que faz o produtor desacelerar em vez de deixar o sistema cair.

component: diagram-wrap (segundo diagrama de fluxo)

Sem esse sinal, o sistema escolhe entre duas mortes: estourar memória ou descartar widgets em silêncio. Com backpressure, o produtor recebe um "segura aí" explícito e a degradação vira uma decisão, não um acidente.

Revisão imediata — antes de fechar

Clique em cada card para revelar. Não precisa acertar — o objetivo é ativar a memória.

O que é sharding de widgets?
Repartir a base entre N nós por uma chave — cada nó guarda 1/N dos widgets.
Quando usar replicação?
Quando a morte de um nó não pode derrubar a fatia dele — custa 2× de disco.
Sharding vs. replicação?
Sharding reparte dados diferentes; replicação copia os mesmos dados.
O que backpressure evita?
Buffer estourando a memória e descarte silencioso de trabalho.
Maior risco do sharding?
Escolher a chave errada — mudá-la depois custa uma migração inteira.
